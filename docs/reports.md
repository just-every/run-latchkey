# Security reports

Unlock your company vault, open Settings, then Security reports. The current vault owner can inspect permitted active items and retained successful connected human activity. Other readers and reviewers cannot open this initial reporting door. Personal and family vaults are excluded.

Choose 7, 30 or 90 days, or 12 months. Member reference and Item reference accept an opaque account or item UUID. Leave either empty to include all permitted activity. Usage action narrows the recorded action. These criteria filter usage only: posture and adoption keep the complete current vault scope, so selecting one member never makes the health denominator smaller.

Save report view retains the range and usage criteria inside an additional owner-encrypted envelope. A vault reader cannot decrypt these new view criteria. Existing legacy saved views remain readable to the reporting owner; previously shared bytes are not recalled. Selecting a saved view restores them; Generate report observes current sources again. A saved view is not a historical observation. CSV and PDF downloads include the exact selected criteria, as-of time, policy version and unknown coverage. Changing a criterion clears the old report. Changed vault authority or source revision requires a fresh report before export.

No matching usage means no matching retained facts, not proof that an item was never used. Missing machine, agent, offline and client-reachability sources remain unknown. Broader team and auditor authority and complete source coverage remain incomplete under LKY-013.

## Dated observations

Use **Retain today’s encrypted observation**, then **Capture today**, to save the current company-vault posture and adoption. Capturing requires the current vault owner and live read authority. Only the first explicit capture for a UTC date is retained. A duplicate refuses rather than replacing that day. The capture checks the current item revision, recipient and enrollment inventory and installation roster counts. It must describe the current date and be no more than five minutes old; the product provides no backfill door.

Each encrypted observation freezes its as-of time, observation freshness, source revision, score policy definition, denominator, risk and unknown counts, adoption and coverage. It contains neither item titles nor secret values. Saved usage criteria do not narrow a posture observation. Editing an item changes future observations and never recalculates earlier scores. The present policy remains the conservative confirmed-clear share; unknown items cannot become clear.

**Show retained history** uses the selected 7-day, 30-day, 90-day or 365-day daily view. Every absent UTC date is a gap. Monthly summaries include all retained observations, including those older than the daily window, and identify missing dates and whole missing months. A mean score averages scored observations, with scored-day and observed-day counts disclosed; an empty denominator has an unknown score. Policy versions stay separate. Exact-date comparisons use 7, 30 and 90 days earlier and the same calendar date twelve months earlier, clamping leap day to February 28. Missing baselines and policy boundaries have no numeric delta. No comparison is evidence of provider remediation.

History CSV and PDF include frozen observation metadata, coverage, adoption, daily gaps, monthly summaries and comparison baselines. Every download rechecks current vault ownership and the retained-history fingerprint. Item changes alone do not invalidate historical scores. Erasure does invalidate the affected retained history and refuses an old in-memory export. Downloaded files cannot be recalled.

Report data has its own random key wrapped only to the capturing owner. Shared vault readers cannot obtain it through the report door. Records archives retain the encrypted observations and key envelope as data; historical grants do not activate on restore. The existing exact source-owner approval rewraps that report key to the destination owner, and only separately reviewed destination activation admits report reads. Rotating ordinary vault access does not rewrite these observations.

Reviewed item erasure removes all report observations for that vault. Reviewed person erasure removes tenant report observations because adoption can include installation roster counts. Neither operation rewrites old scores to hide a subject. Later erasure journals fence older installation archives, and stale capture revisions cannot recreate removed observations. Outstanding recipient, device and backup copies remain incomplete under LKY-034. No automatic capture, audit expiry or destructive retention process is enabled.
