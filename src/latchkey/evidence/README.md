# Evidence delivery transports

`adapters.mjs` is a client-side transport module. Never expose it as a server URL-fetch proxy: self-hosted Evidence deliberately accepts buyer HTTPS origins, including private networks, and literal HTTP loopback installations. Other destinations allow only their exact official HTTPS origins. Endpoint paths are fixed by the adapter; credentials, URL userinfo, query strings and redirects cannot select another host.

The caller verifies the signed `packageValue`, previews its fields, confirms authorization immediately before dispatch, and retains the package and delivery obligation. The module does not persist credentials, sign packages, approve compliance, automatically retry, or log request/response content. Bearer credentials are strings; Secureframe uses `{apiKey,keySecret}`. `target` is an existing Evidence requirement ID, Vanta document ID, Secureframe test ID, or Drata evidence name. Drata additionally requires a positive numeric workspace ID. Dates are UTC `YYYY-MM-DD`.

The result is `{state,providerReference,retryable,status,stage}`. `stage` is a checkpoint object with `name`, package/destination `binding`, and, after a successful Vanta/Drata upload, `uploadReference`. A caller can pass a previous failed `submit` or `create` stage as optional `resume` to skip the completed upload. Preserve it privately. A completed checkpoint cannot be resumed. Each call attempts each remaining stage once. Treat transport failures and malformed success responses as ambiguous backlog with `retryable:false`; reconcile provider state before another create. Retryability on an HTTP error describes the failed stage only. Never restart the whole flow blindly after a partial success.

Vanta upload is draft until submit succeeds. Drata creation requires both artifact counters and the returned artifact list to confirm the single requested artifact. Secureframe's published operation has a default response without a successful ID schema: HTTP success is transport acceptance and `providerReference` remains null unless a same-origin Location header is returned. Show that missing reference honestly. No adapter claims auditor approval, external erasure, or signature verification by the receiver.

Primary specifications consulted 22 October 2026:

- Evidence's own `/v1/openapi.json`, generated by `src/evidence/api/openapi.ts`, with validation in `src/evidence/api/http.ts` and `src/evidence/upload.ts` (sibling run-evidence source revision `f3f2f470169fa02a4fb6d6b753ae1190f75c2d2c`).
- [Vanta upload schema](https://developer.vanta.com/api-reference/documents/upload-file-for-document.md), [submit schema](https://developer.vanta.com/api-reference/documents/submit-document-collection.md), [upload guide](https://developer.vanta.com/docs/guides/upload-a-document.md), [authentication](https://developer.vanta.com/docs/concepts/authentication.md). OpenAPI says upload 201/submit 204; the guide says 200, so both documented success statuses are accepted with upload metadata validation.
- [Drata v2 Evidence](https://developers.drata.com/openapi/reference/v2/tag/Evidence/), [v2 base path and Bearer usage](https://developers.drata.com/openapi/reference/v2/overview/), [official regional hosts](https://developers.drata.com/api-docs/). File upload precedes evidence creation; API base path is `/public/v2`.
- [Secureframe API](https://preview-api.secureframe.com/docs/introduction.html), [official test-evidence endpoint explanation](https://support.secureframe.com/en/articles/15111235-faqs-tests-and-controls-evidence-frameworks-and-troubleshooting). Authentication is the key and secret separated by one space, not Bearer.
