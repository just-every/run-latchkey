# Client health checks

Open **Settings → Password health** in an unlocked vault. **Check locally** reads current permitted active items. **Check with HIBP** additionally requests Pwned Passwords ranges and the public website breach catalogue. Every range request carries only five hexadecimal hash characters, requests padding, omits credentials and referrers, bypasses persistent cache and refuses redirects. Matching suffixes and reuse comparisons remain in this client. Ranges are deduplicated within one check. Failed or malformed feeds are unknown coverage, never healthy results.

The current reuse method compares values already decrypted under this caller's vault rights, only in memory. No comparison index, reusable password digest or plaintext dictionary is sent to the service. This implementation does not yet compare an entire organization or claim an independent privacy review. Disconnected clients and inaccessible vaults are not represented as healthy.

Local findings cover password length and diversity, reuse, insecure HTTP fields, expiry dates and owner-recorded password age. Card expiry accepts a year and month, with expiry at the start of the following UTC month. Document expiry uses a date. The optional `passwordChangedAt` date field supplies owner-recorded website chronology. A verified HIBP breach strictly after that date raises a separate website finding; equal dates, missing dates, future dates and unverified reports do not establish that chronology. Both dates and the limits of this owner-recorded observation remain visible. This is not proof that a provider accepted a password change.

An optional token calls the GitHub authenticated-user API directly from this client. MFA is observed only when the response supplies its boolean configuration and the login matches the permitted item's username and GitHub origin. Missing fields and all other supported-factor coverage remain unknown. The token is panel memory only and is discarded when the panel unmounts; it is never stored with findings or sent to the Latchkey service. Prefer the minimum provider permission needed to read your own account configuration. No provider configuration is changed here.

Findings include permitted item links, vault owner, source and observation time. A member or vault owner with current read access can record an actor-signed, actor-encrypted suppression in their own history namespace without receiving item-write or administrative rights. Reasons, finding categories and observations remain encrypted. Suppression leaves the current risk count unchanged, expires at the selected time and does not survive an item version change. Expiry is evaluated on history reads, at inspection completion after feed work and when the panel renders. A local timer updates an idle panel without another feed request. Retained observations and reasons remain visible as inactive history. Earlier shared-vault observations remain inactive because their payload cannot authenticate its named actor. Reports are recomputed rather than persisted. The vault revision and current read authority are checked after feed work and every fifteen seconds while a report is open; changed sources clear the report and require a fresh check.

A changed vault value can remove its present local condition, and a fresh GitHub response can remove its observed MFA condition. Generic provider-password verification, supported passkeys, complete SSH practice checks and reviewed organization comparisons remain incomplete. A task completion or suppressed finding is never provider remediation evidence.
